# D3D11 FL9_2 blockers

**Certification status: INCOMPLETE.** Review baseline: `aa7b65c43ef008d0a92d20fcdf9f10fa0883f157`. A native feature-level guarantee, a wgpu capability report, and a hardware result each require independent evidence. Compare the current test and hardware ledgers for checks added after this baseline.

## Shader profile and pipeline coverage

FL9_1 and FL9_2 both use FXC's `vs_4_0_level_9_1` and `ps_4_0_level_9_1`. Both levels have the same vertex limits (256 instructions, 12 temporaries, static flow nesting of one) and pixel limits (64 arithmetic instructions, 32 texture instructions, 12 temporaries, four levels of dependent reads). The numeric suffix names an FXC target shared by both feature levels. `selected_shader_profile` in `wgpu-hal/src/dx11/hal_shader.rs` already chooses these profiles for vertex and fragment stages. Keep the same targets and reuse the selected-entry Naga lowering and legality checks. [Microsoft compiler targets](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/specifying-compiler-targets) · [10Level9 device methods](https://learn.microsoft.com/en-us/windows/win32/direct3d11/d3d11-graphics-reference-10level9-device)

The fork exposes narrow WGSL subsets for operations including fragment texture load, texture queries, and explicit LOD. Each subset depends on lowering and on the currently bound texture and sampler satisfying the conditions of that lowering. The driver can report `SHADER_LOAD` through the 10Level9 format support algorithm for non-depth formats. FXC applies a separate shader-profile check to HLSL `Texture.Load`. FL9_2's identical target keeps the existing constraints on general explicit LOD, general texture queries, derivatives, vertex texture sampling, integer operations, and shader system values. [Pinned shader contract](../../../wgpu-hal/src/dx11/CAPABILITIES.md) · [Driver DXGI support algorithm](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/required-dxgi-formats)

Windows SDK 10.0.26100.0 x64 and x86 FXC both passed eight compile-only checks on Ben-Desktop. The command used `/Ges /O3 /T <profile> /E main /Fo <output> <source>` in the FL9_2 worktree with disposable source and bytecode under system temp. Both published shared targets accepted simple vertex and implicit-sampling pixel shaders. Both rejected the invented `ps_4_0_level_9_2` compiler target and rejected raw `Texture.Load`, `SampleLevel`, and `ddx` at `ps_4_0_level_9_1` with X4532. Both accepted the `ddx` control at `ps_4_0_level_9_3`. The 193-slot shader was rejected with X5608 and X5609, reporting the 64-arithmetic and 96-total limits. These checks establish compiler behavior for both FXC executable architectures. GPU and UWP shader evidence is tracked separately.

Required shader evidence on a physical FL9_2 device includes compiling WGSL through Naga and FXC, creating both shader objects, drawing, and checking pixels for each newly projected resource or state. Re-run the corresponding FL9_1 cases through its unchanged entry points. Compile and reject representative over-budget shaders and unsupported shader operations. Include a multi-entry case with an unsupported operation reachable from only one entry point, and verify that selecting the supported entry preserves compilation and output. FXC acceptance establishes compiler legality. Draw and readback establish selected-device behavior.

## Native behavior without a corresponding public operation

- **Mirror once.** The experimental DX11 HAL now provides a device-owned sampler with per-axis Mirror Once addressing. The native path has a patterned 2D readback that distinguishes it from Clamp and MirrorRepeat. Portable wgpu sampler descriptors have no corresponding address mode. Cube, volume, comparison, and LOD-specific operation coverage remains open. [D3D11 address modes](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ne-d3d11-d3d11_texture_address_mode)
- **Bounded texture repeat.** Typed HAL sampling can exercise a POT texture with an exact 2,048-cycle coordinate span on one primitive. Core continues to reject arbitrary Repeat and MirrorRepeat at a finite span ceiling. Static sampler state cannot establish the span of interpolated or computed coordinates. More dimensions, wrap modes, and conditional-NPOT controls remain open. [Direct3D feature levels](https://learn.microsoft.com/en-us/windows/win32/direct3d11/overviews-direct3d-11-devices-downlevel-intro)
- **Native occlusion sample counts.** The DX11 HAL now has owned numeric queries with device validation, one-shot recording, reset generations and a bounded result read. The physical fixture checks a count greater than one, a separately submitted reset generation returning zero, and retained old results. Portable resolves return 0 or 1. Error recovery with in-flight GPU work and independent historical-driver coverage remain open. [D3D11 query types](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ne-d3d11-d3d11_query)
- **Automatic mip generation and native resource access.** Where D3D11 supports `GenerateMips`, the public API has no equivalent fixed-function command. A caller can render or copy individual mips where the projected operations permit it. Direct3D staging or lock semantics are also separate from wgpu's buffer mapping and texture copy contract. An ordered CPU-shadow readback validates wgpu's byte contract but leaves the native staging or driver operation to native tests. [Required DXGI formats and support algorithm](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/required-dxgi-formats) · [Pinned texture contract](../../../wgpu-hal/src/dx11/CAPABILITIES.md)
- **Native format names and operation bits.** DXGI's 10Level9 display and back-buffer-cast capabilities are not application texture-usage flags. For example, the DXGI driver table includes `B8G8R8X8_UNORM` and its sRGB variant, which lack direct wgpu texture formats. Record each native format/operation pair and prove the public equivalents separately. [Required DXGI formats](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/required-dxgi-formats) · [wgpu format enumeration](../../../wgpu-types/src/texture/format.rs)
- **Legacy driver limits.** The WDDM driver contract records `MaxVertexW` of `1e10` for FL9_2. wgpu has no limit or capability entry for this D3D9 DDI field. A native clip-space stress fixture can characterize the selected driver. A public claim would need a defined wgpu behavior and matching coverage. [Required Direct3D 9 capabilities](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/required-direct3d-9-capabilities)

## Implementation and evidence still needed

- **Surface Pro X stencil.** Exact FL9_2 on the Adreno 680 driver
  `27.20.2160.0` produced a red pixel at (4, 0) on a back-facing region that
  should have remained opaque black. The failure reproduced in the isolated
  test. The direct-native control passed both winding conventions on RTX 3090 Ti.
  The Surface Pro X SSH connection timed out, blocking the same-driver native
  reproduction and verification of a workaround. The adapter-specific gate disables asymmetric stencil on
  `4d4f4351:41333430`. Full FL9_2 still requires correct back-face behavior.
- **Query replay failure.** The query result read has a five-second deadline.
  The existing cleanup fence can still wait indefinitely if a driver stops
  making progress without reporting device removal. A robust retirement path
  needs to retain in-flight resources until the GPU completes or the runtime
  reports removal.

- **FL9_2 sampler range.** The review baseline caps the HAL sampler and capability projection at anisotropy two. FL9_2 supports sixteen. Show the selected-level descriptor ceiling and actual minification with a matched 2/16 controlled texture. Keep the shared integer MinLOD, maximum FLT_MAX and conditional-NPOT rules. Use the existing lowering guard for samplers whose finite LOD clamps require view-dependent adjustment. [10Level9 device methods](https://learn.microsoft.com/en-us/windows/win32/direct3d11/d3d11-graphics-reference-10level9-device)
- **Raster, blend and input assembly.** Independently validate distinct alpha/colour factors, front/back stencil, overlap at a shared stream offset, native R16/R32 index behavior, and primitive/index maxima of 1,048,575. Draw/readback should distinguish a front from a back face, verify the alpha channel independently of RGB, and exercise indices above 65,535. Test public validation or documented emulation for values beyond the guarantees. An over-limit D3D11 runtime success is device-specific evidence. [Direct3D feature levels](https://learn.microsoft.com/en-us/windows/win32/direct3d11/overviews-direct3d-11-devices-downlevel-intro) · [10Level9 device methods](https://learn.microsoft.com/en-us/windows/win32/direct3d11/d3d11-graphics-reference-10level9-device) · [10Level9 context methods](https://learn.microsoft.com/en-us/windows/win32/direct3d11/d3d11-graphics-reference-10level9-context)
- **Per-format limits.** The DDI table lists additional required operations at FL9_2 for RGBA32_FLOAT, RGBA16_FLOAT, RG16_FLOAT, R32_FLOAT, R16_UNORM, RG16_UNORM, RGBA16_UNORM and RG16_SNORM. Optional filtering and blendability need independent query evidence. Test typed creation, dimension and mip limits, sampling, rendering, copying, and readback for every operation projected. The broad feature table lists a guaranteed volume extent of 256 through FL9_3 and the API-specific `CreateTexture3D` table lists 512 for FL9_2/9_3. Record 256 and 512 creation and usage separately. The WDDM stencil bit at FL9_1 differs from the 10Level9 API's documented FL9_1 two-sided stencil restriction. The WDDM `R16_UNORM` requirement at FL9_2 also differs from the functional specification's stated limitations on reporting that texture support. Resolve runtime-facing cases with selected-device operations and leave unsupported operations out of the advertised wgpu contract.
