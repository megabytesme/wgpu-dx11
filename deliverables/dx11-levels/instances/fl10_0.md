## Ordered implementation and test gates

1. Wire SM4.0 `vs_4_0` and `ps_4_0` with real device creation plus expected pixels. Exercise dynamic loop/indexing, integer arithmetic and explicit LOD/vertex texture sampling. Bind b13, t127, s15 and constant vector 4095 in representative native probes. Validate wrong register, shader over-profile, bounds, and 10_1-only shader failure. Native `gs_4_0` and stream output need adjacency, emit/cut, overflow and DrawAuto tests.
2. Add 8192 1D/2D/cube axis, 2048 volume and 512 layer fixtures at tractable sizes. Expose ordinary 2D arrays with sentinel data at terminal layer and mip, `512/513` boundaries, and reject cube arrays. Prove unrestricted NPOT mips/wrap, typeless and texture view compatibility, BC4/BC5 signed/unsigned, D32F/D32F-S8 native creation, and sentinel depth/stencil sampling where valid. Execute all required per-format usages, not just Dxgi query or local creation.
3. Exercise 16 IA slots and reject slot 16, verify native SV_VertexID and SV_InstanceID with overlapping slot semantics, list/strip cut, U16/U32 and signed base. Draw to eight RTs with unique values, shared blend equations and independent write masks/enable. Reject ninth target and differences in equations. Test alpha-to-coverage, depth-bias clamp, depth/stencil mip view, linear sRGB blending and actual support for each MSAA count. Resolve allowed formats and reject illegal resolve descriptors safely.
4. Run zero/nonzero occlusion, pipeline statistics over a known draw and timestamp validity via disjoint brackets. Probe native event/predication/stream-output query cases separately. Test generation ordering and query reuse with native and public observations.
5. Query `D3D11_FEATURE_D3D10_X_HARDWARE_OPTIONS`. In a separate optional packet, execute `cs_4_0` at one raw or structured buffer UAV, verify 256-byte raw alignment, 768 invocations and Z=1. Positive cases include legal group-memory sharing. Negative cases include a second UAV, typed texture, atomic, indirect and cross-thread writes. Preserve unsupported results without raising compute, storage or indirect public capabilities. FL10_x indirect draws and dispatch are unavailable.

## Native/public blockers

Geometry stage, primitive adjacency, stream output/DrawAuto, multiple native viewports, cull distance, 1D arrays, native typed buffer views, sampler details and native query modes require extensions or stay blockers. BC4/5 requires a representable subset contract as the monolithic BC feature includes BC6H/BC7. FL10_0 lacks independent blend equations even with multiple attachments. Public compute cannot be inferred from optional native SM4.0 compute.
