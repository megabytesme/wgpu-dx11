## Coordination procedure

1. At the milestone read `requests/<role>.md`, applicable entries in `decisions/`, and the current role statuses. Publish proposed path assignment, base full SHA, intended worktree/branch and downstream consumers in the role handoff or request to the appropriate owner. Mission Control confirms which active work packet is responsible for any overlapping tracked path.
2. Verify the assigned checkout and exact starting commit, and inspect both its working tree and other affected role status. Layer independent fixtures or proposals into a distinct new path when an existing file is occupied. Use alternate worktrees to isolate review and nonoverlapping implementation. A path under active edit requires an explicit assignment transfer.
3. During an active assignment, keep the path list current in shared handoff. If a consumer needs a shared-file change, provide interface, patch or repro evidence to the current writer. Transfer an assignment only after the current writer has finished its active edit and published the base, working diff or commit, tests and proposed next action. The receiving writer confirms the handoff before editing. Avoid overwriting, stashing, cleaning or resetting another lane.
4. Before integration prepare exact locked commit provenance, diff/path list, capability and feature-disabled behavior, evidence IDs, focused tests and affected earlier/later lanes. Compare patch paths against the candidate and proposed neighboring patches. The integration owner applies approved changes one tier at a time, expiring the path assignment once the handoff is complete.
5. Reuse the shared resource locks for physical activity, including `locks/lumia-950-xl.lock`, `locks/surface.lock`, `locks/desktop-gpu.lock` and `locks/desktop-rust-release.lock` when applicable. Keep code ownership and device acquisition records independent. The role status carries UTC, full source SHAs, exact worktree, state, evidence, blockers, next action and current device lock. ## Independent work when integration is occupied

- Per-tier native requirement audit, Microsoft table extraction, HAL and public API static inspection, compiler target tests and conformance case design can use the pinned checkout in read-only mode.
- New fixture files can advance after assignment when they do not need edits in existing leased files. Supply test registrations, fixture adapters and common harness proposals to the assigned writers.
- Product graphics analysis can inventory settings, shader variants and configuration while the existing HDR and DX11 lanes retain their own source pathways. A product test of a new fork SHA must use the candidate dependency and verified package identity.
- Record unavailable historical hardware, active device locks and missing runtime/package prerequisites as case-level blockers. Explore other independent work while those cases wait. Preserve placeholders in the certification matrix and route each gap to an explicit owner.
