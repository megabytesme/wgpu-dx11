# FL9_1 certification blockers

**INCOMPLETE.** The candidate covers additional volume-texture operations and fixes misleading strict-mode results. The requirements below block a certification gate.

| Requirement | Observed gap | Evidence needed to close |
| --- | --- | --- |
| BGRX8 linear and sRGB | Both DXGI formats returned required driver flags and produced mip readbacks in the native control. The public `TextureFormat` enum and DX11 texture mappings lack corresponding formats. | Add fork format variants or an explicitly scoped native interop path. Define opaque-alpha semantics, compatible views, upload, filter, copy, attachment, blend, readback and format rejection. |
| Native mip generation | The native control populated both lower levels of all seven documented 2D formats on the RTX and Adreno. The wgpu command encoder and DX11 HAL lack a reachable native generation operation. | Add a backend operation and explicit caller-facing API or interop entry point. Test valid SRV ranges, absent creation flags, unreadable formats, linear and sRGB output and rejection on FL9_1 volumes. A render-based generator could cover equivalent image results under a separate contract. |
| FL9_1 blend and sampler semantics | Native encoded-space sRGB blending differs from wgpu's linear-space requirement. Core also rejects repeat and mirror-repeat under the finite native limit of 128 repeats per primitive. | Implement and test linear-space blending where the backend can preserve wgpu semantics. For repeat modes, require a provable coordinate bound or a correct periodic sampling implementation that preserves filtering, mip selection and derivatives. |
| 10Level9 clipping and shader budgets | FXC accepts six clip planes on the supported runtime profile. The DX11 projection lacks a clip-distance API and DXBC passthrough. Eight user varyings fit only when the pixel signature omits `SV_Position`; Naga retains a declared unused field. | Provide a reachable clip-plane path with positive and negative GPU reads. Prove remaining exact instruction, sampler, temporary-register and dependency boundaries in actual draws. A future eight-varying increase requires selected-entry input pruning and distinct per-location readbacks. |
| Other native operations | The matrix records direct texture map, shared-resource paths, driver-level fixed function and output controls, and cube-face render/cube-depth limitations. Some source tables describe driver obligations while the 10Level9 API restricts the application operation. | Add scoped native controls and, where the literal goal requires reachable wgpu behavior, define an extension or emulation. Resolve all `SOURCE_DIFFERENCE` rows against the runtime and intended API surface. |
| Historical hardware and true removal | Exact FL9_1 on RTX 3090 Ti and Adreno 680 validates those execution paths. Their D3D11 ceilings are FL11_1. Fixture-based surface failures and the nominal removed-reason check leave physical removal and recovery unverified. | Supply a physical adapter whose maximum D3D11 feature level is 9_1, with its original driver. Arrange an isolated and recoverable physical removal test. |
| ARM32 Lumia presentation and low memory | Direct LAN TCP reached the configured portal. The Windows PowerShell pinned-certificate endpoint returned HTTP 503, and the later HTTPS retry timed out. Earlier signed forced-FL9_1 gameplay logged audio without a game frame. The candidate's ARM32 offscreen import check used panel-host stubs. | Make the paired portal respond, then deploy a uniquely identified signed fixture using the real host. Collect exact feature level, CoreWindow presentation, rotation, suspend/resume, recovery and the 4 MiB gameplay fallback on a copied world. |
| Surface signed UWP presentation | Native ARM64 and public Win32 offscreen execution passed. The Surface console was locked. Prior signed product gameplay used the FL9_1 compatibility path on FL11_1. | Unlock the interactive console and exercise a separately signed candidate using the real SwapChainPanel and required product fixtures. |
| Remaining public and conformance coverage | Public suites, standalone native controls and the matrix provide partial evidence. `tests.json` records the exact CTS extent and x86 suite outcomes. | Complete conformance beyond the curated inventory, independent reference comparisons, fuzzing, required enable/disable capability tests, readback for unresolved format and operation cells, product and performance regressions, and independent gate review. |

A backend-specific extension through the guarded `Device::as_hal` entry point could expose native BGRX resources and commands. An implementation would need to keep the immediate context serialized and preserve wgpu's initialization, ordering, memory ownership and fence contracts. Native-format import into portable wgpu textures would also require explicit compatible resource and view rules.
