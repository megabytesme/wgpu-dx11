# Direct3D FL11_0 and FL11_1 research

Source audit at wgpu `aa7b65c43ef008d0a92d20fcdf9f10fa0883f157`. Both tiers are **INCOMPLETE**. The native feature-level bullets describe Microsoft requirements. The tests below are planned, and each needs an exact-level physical result before promotion. The public API gaps require a product decision and implementation even if every native-only probe succeeds.

## FL11_0 entry contract

FL11_0 requires shader model 5.0, including `vs_5_0`, `ps_5_0`, `gs_5_0`, `hs_5_0`, `ds_5_0` and `cs_5_0`. FL10_1 already requires geometry shaders and stream output, covers cube arrays and BC4/BC5, and permits optional restricted DirectCompute 4.x. The new mandatory work includes hull/domain tessellation, full DirectCompute 5.0, BC6H/BC7, resources and formats expanded for FL11, and indirect execution. A D3D11 device selected at FL11_0 can still use earlier compatible profiles where needed. ## Promotion evidence

First land resource shapes, typed views, format and usage baselines, then SM5 vertex/fragment paths and FL11_0 render targets, then CS/PS UAV allocations, compute, indirect and queries. FL11_1 adds its independent binding budgets, vertex writable storage and runtime feature operation probes. Native-only work packets can develop against exact-level devices in parallel while the owning integration changes land in file order. Do a fresh full FL9_1 through FL10_1 regression pass before either promotion, and a full FL11_0 pass before FL11_1.

Every physical result needs adapter LUID/vendor/device, driver version, OS/WDDM, architecture, requested and returned level, `GetFeatureLevel`, query values or HRESULTs, shader profile and workload/case identifiers, deterministic readback, validation-layer messages where available, and elapsed/time-out context. Run with D3D_DRIVER_TYPE_UNKNOWN plus explicit physical DXGI adapter where platform permits, preserve software flags, and use WARP only when clearly labeled as software. A higher-capability desktop forced down is valuable for profile boundaries. Genuine FL11_0 hardware remains required to distinguish a higher-tier driver’s optional features from guarantees and to exercise historical constraints. AppContainer packaging, the Lumia ARM32 availability, Surface ARM64 availability and desktop exact native device coverage remain separately recorded.

For public acceptance run the repo's DX11 GPU tests and explicit CTS cases for limits, rendering, shader validation, texture formats, bindings, synchronization and indirect workloads on exact-level devices. Any public case running through a fallback backend is invalid evidence. For native-only acceptance retain a failing product-level gate while the public path is blocked, even when a native HLSL readback passes.
