### HDR dependencies

HDR requires both shader/attachment semantics and presentation. Horizon upstream renders scene-linear content into FP16, applies tone mapping, and chooses output policy from actual surface support. The separate HUD/coverage layer depends on independent blending. Horizon's Windows paths can use 10-bit RGB10A2 with BT.2020/PQ or supported FP16 with extended-linear sRGB. A higher feature level or an HDR display alone is insufficient. The pinned D3D11 surface's only format/color-space pair is BGRA8/sRGB. FL9_2 render-target support for a float format and FL9_3 additional float blending also do not imply the required blend or swapchain contract. [Pinned graphics](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/docs/graphics.md), [pinned HDR formats](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/crates/horizon-client-render/src/gfx/hdr.rs#L160), [Microsoft Advanced Color](https://learn.microsoft.com/en-us/windows/win32/direct3darticles/high-dynamic-range).

An HDR certification case needs actual output or composition contract, OS Advanced Color state, SwapChain3 `CheckColorSpaceSupport` with PRESENT bit and `SetColorSpace1`, optional metadata HRESULTs, descriptor and selected draw/compose/HUD pipeline, and known color patches at controlled settings. Composition cannot use the ordinary swap chain's `GetContainingOutput`. Use product or platform output evidence. Exercise an SDR fallback, a supported HDR output, a resize/monitor or display-mode change and combined layout on each eligible surface type. Preserve both the actual display result and raw linear render/readback where offered. Production application HDR implementation and deployment are outside this roadmap worktree.

## Horizon shader API and Iris/OptiFine path

Horizon Shader API 0.2 uses schema 1, root `horizon-shaders.toml`, manifest-referenced WGSL, and the same native loader for a folder or packaged `.hshader`. The 0.2 checker and package commands validate source and package semantics. Color values are linear with BT.709 default and optional BT.2020 primaries. Stage-specific inputs may contain generated bindings and helper contracts. It supports material/vertex, sky/weather, entity, post, tonemap and advanced paths including history, shader-pack compute and kept resources, motion, and traced scene inputs. Retired API 0.1 must be refused clearly. A structurally valid 0.2 pack is only eligible for runtime if the exact device, limits, stage and resource requirements are supported. [Pinned authoring guide](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/docs/shaders.md), [pinned API reference](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/docs/api/shaders-reference-0.2.md), [manifest constants](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/crates/horizon-shader-api/src/manifest.rs#L5).

Iris/OptiFine-style packs use the separate `shaders/` loader for GLSL programs, properties, and layout variants such as terrain and post programs. Default and legacy dimension handling, shader-rewrite behavior, settings and GLSL frontend evidence belong to that path. The product patch also changes Cargo's Naga override around line 1839, making exact Naga identity relevant. Successful Horizon WGSL authoring or runtime tests do not verify the separate frontend and wrapper. Both feed renderer capabilities and must be tested independently, including specific program outputs. [Pinned compatibility specification](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/docs/cleanroom/shader-packs-spec.md), [pinned loader](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/crates/horizon-shaders/src/lib.rs).

Current UWP `patches/nightly-2026-11-20/horizon-uwp-0.1.15.patch:9987` selects FL9_1 compatibility based on the DX11 backend alone, even on a device that reports FL11_1. The restricted path builds a 2D atlas and compatibility shader family and preserves its world scaling pass. Upstream modern terrain binds 2D arrays and uses derivative-based sampling, and advanced packs can demand 2D arrays, multiple color outputs, float targets, storage, sample counts and shader facilities beyond a single feature toggle. Renew the app opt-in with a versioned explicit public renderer profile plus granular adapter and pipeline features. Treat extension combinations as new behavior and maintain the atlas path for earlier tiers. [Pinned terrain WGSL](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/crates/horizon-client-render/src/terrain.wgsl#L51).

## GPU culling, timing and performance

Upstream GPU terrain culling has a separate gate at `gfx/gpu_culling.rs:525`. It requires suitable multidraw and batching, `MULTI_DRAW_INDIRECT_COUNT`, `COMPUTE_SHADERS`, at least eight storage buffers per stage, and driver/backend restrictions. Native D3D11 FL10.x optional compute permits a narrow UAV model. FL11_x dispatch and single indirect draw still do not establish the public count-driven multidraw contract. Preserve CPU culling unless that entire application path executes. `HORIZON_GPU_CULL` at upstream `gfx.rs:4307` controls a separate occlusion path. Use product graphics setting and capability logs to distinguish them. [Pinned GPU terrain culling](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/crates/horizon-client-render/src/gfx/gpu_culling.rs#L525), [pinned graphics settings](https://github.com/horizon-rust/horizon/blob/0a875da91dbb0fdcb7ba8c42c11341aa229af51a/docs/graphics.md).

GPU time requires a working timestamp path, disjoint handling and plausible ticks at advertised frequency. In the baseline fork `query.rs:119` measures capability and `hal_device.rs:1166` handles public timestamp query creation. Horizon `gfx/timing.rs:76` gates the timer on advertised features. A documented Surface DX12 run produced an invalid reported time of roughly 619 trillion ms, which cannot be used as duration evidence. Patch 0.1.15 around line 12465 switches timing source after three invalid whole-frame result sets and returns after three valid results, with reset measurement windows. Its isolated controller tests passed. A matched rerun must prove the new behavior on the signed Surface app. Compatibility fallback uses active frame pressure, CPU work and waiting, excluding deliberate pacing sleep.
