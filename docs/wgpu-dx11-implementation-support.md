# Independent D3D11 implementation checks

The native reference harness ran on a physical RTX 3090 Ti using x64 and x86 processes on Ben-Desktop. Both builds passed all seven exact-device requests and all applicable controls on each of two RTX DXGI adapter identities with distinct LUIDs. Every request matched the feature level reported by both creation and `GetFeatureLevel`. The original signed Surface Pro X ARM64 smoke passed the seven exact-level draw cases and four compute cases. The updated ARM64 probe was signed and verified, and its execution is pending because SSH at `192.168.1.227:22` timed out twice. The Lumia pinned HTTPS helper timed out at `/api/os/devicefamily` before the signed 1.0.0.0 package could be deployed, so the phone's maximum D3D11 tier is unverified. | Control | Requirement and oracle |
| --- | --- |
| FL9_1 onward BGRX8 and mips | `FL9_1.OP.bgrx8_unorm`, `FL9_1.OP.bgrx8_unorm_srgb`, `FL9_1.OP.native_generate_mips`. Create typed BGRX views, fill three mips with different base and lower-level colors, generate mips, copy to staging and sample the SRV. Compare all copied RGB texels and all 64 sampled RGBA pixels. X padding is excluded from BGRX comparison. An RGBA8 resource created without the autogeneration flag preserves lower-level sentinels when the autogeneration call is made. The sRGB fixture uses channel endpoints, so separate non-endpoint linear-light and rounding tests remain open. |
| FL9_1 versus FL9_2 sampler | `FL9_2.OP.mirror_once`. The sampler creation returns `E_INVALIDARG` at exact FL9_1. At FL9_2 and above, sample at the same negative coordinate with Mirror Once and clamp. Read all 64 pixels and compare blue versus red. |
| Numeric occlusion | `FL9_2.OP.exact_occlusion_count`. Verify creation rejection at exact FL9_1, then read 0 samples with no draw and 64 samples after a full-target draw at FL9_2 and above. The positive count distinguishes exact samples from a Boolean. |
| FL9_2 asymmetric stencil | `FL9_2.OP.two_sided_stencil`. Front-facing geometry replaces the initial stencil value. Opposite winding uses increment. Both correct references pass all 32 pixels on each half. Swapped references leave all 64 background pixels intact. This is a native RTX observation. Pair this exact assay with the public candidate on Adreno before attributing the Adreno failure. |
| Shader stages | Geometry executes at exact FL10_0 and above with the tier’s VS/PS/GS profiles. VS clip distance and PS discard each alter pixel coverage at a controlled boundary. FL11_0 and FL11_1 execute three-control-point hull/domain tessellation. Readback uses fresh staging resources and a distinct known background for each shader-stage case. |
| Multisample resolve | Exact FL10_1 and above. Write magenta into one of four samples and leave three green. Resolve into a single-sample texture and compare all pixels including the mixed output. A texture descriptor with 33 samples is rejected. |
| 11.1 interface and output-merger | `FL11_1.OP.options_clear_view`, `FL11_1.OP.logic_ops`. Query Device1 and Context1, verify an integer clear rectangle and its neighbours, then XOR the framebuffer with known integer PS output and read all 64 pixels. Blend-only and logic-only descriptors with valid fields succeed. The descriptor enabling both is rejected. |
| Compute | Profile-specific shader dispatch writes four distinct words to a structured UAV and reads them through staging. FL10.x uses the optional Shader 4.x query. FL11.x executes SM5. |

The harness reports a known limitation during exact creation as `PARTIAL` when at least one tier ran and all executed controls passed. Unexpected creation errors, readback failures and device removal fail the probe. Continue to use separate evidence rows for native operations, device capability queries, HAL, and public wgpu behaviour. Full dimension, format and view permutations, physical native-ceiling hardware, and positive Adreno stencil results remain pending.

## Build and rerun

Launch from the roadmap checkout on Ben-Desktop with MSVC 14.44.35207 and Windows SDK 10.0.19041 FXC. ARM32 links using SDK 10.0.15063. The reviewed output directories are under `%TEMP%\dx11-roadmap-qa-nov21-<arch>-reviewed`. Use fresh output directories for new builds. For ARM32 or ARM64, supply the project icon directory and the verified existing development signer.

```powershell
$probe = '.\deliverables\dx11-levels\probe'
& "$probe\build.ps1" -Architecture x64 -OutputDirectory "$env:TEMP\dx11-qa-x64-new"
& "$probe\build.ps1" -Architecture x86 -OutputDirectory "$env:TEMP\dx11-qa-x86-new"
```

Under the desktop GPU lock run each executable and retain stdout as UTF-8 and the actual exit code. `parse-probe.py` reads both raw schemas. Under the Surface lock use the signed 1.0.0.1 ARM64 package with `run-surface.ps1` and a fresh LocalState report. Under the Lumia lock retry the paired preflight and deploy the already signed 1.0.0.0 tier smoke first. Follow the [device compatibility instructions](wgpu-dx11-device-compatibility.md) for exact package activation and shutdown. All tiers remain **INCOMPLETE**.
