## Device selection and ownership

Set `WGPU_DX11_FORCE_FEATURE_LEVEL=11_1` before enumerating adapters from an instance explicitly configured for DX11. The selector accepts the seven D3D11 levels from `9_1` through `11_1`. The legacy `WGPU_DX11_FORCE_FL9_1=1` remains supported. Invalid or conflicting selectors yield no DX11 adapter. Exact selection uses a single native enum, verifies the returned enum and `GetFeatureLevel()`, and filters DXGI software adapters. The automatic mode retains the legacy runtime retry after `E_INVALIDARG`. [D3D11CreateDevice](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-d3d11createdevice)

Native tools can enumerate `wgpu_hal::dx11::NativeAdapter`, open an exact physical device with `open_fl11_1`, and create and own resources through `ID3D11Device1`. Issue native commands through the unsafe `with_immediate_context` callback. It holds the immediate-context lock until command recording or submission returns. Deferred lists can record independently and execute inside that callback. Device access and native diagnostics are independent of wgpu's portable resource tracking. Keep native resources on their creating device unless the documented D3D11 sharing rules apply. [ID3D11Device1](https://learn.microsoft.com/en-us/windows/win32/api/d3d11_1/nn-d3d11_1-id3d11device1) · [ID3D11DeviceContext1](https://learn.microsoft.com/en-us/windows/win32/api/d3d11_1/nn-d3d11_1-id3d11devicecontext1)

`NativeDevice` returns the driver’s D3D11 options, basic doubles, and format support masks separately. The twelve required D3D11.1 option bits are asserted individually. SAD4, extended doubles, and basic doubles are recorded as optional. A successfully negotiated device continues to use the existing restricted public wgpu projection. The native compiler covers FXC SM5.0 vertex, hull, domain, geometry, pixel, and compute, while live public WGSL translation remains on the existing render path. [D3D11 options](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ns-d3d11-d3d11_feature_data_d3d11_options) · [Optional Direct3D features](https://learn.microsoft.com/en-us/windows/win32/direct3d11/using-direct3d-optional-features-to-supplement-direct3d-feature-levels)

## Packed sampling and Rgba8Uint copy follow-up

The optimized FXC bytecode for the original one-thread fixture used a two-channel `sample_l` destination and omitted UAV writes for the green and blue sample channels. The fixture's B5G5R5A1 and B4G4R4A4 texels store their color in those channels. WARP reproduced the black RGB with the same optimized shader for literal and register LOD operands and for default and explicit shader-resource views. Disabling optimization or replacing the unrolled loop with eight explicit stores passed all 24 WARP combinations. The corrected HAL fixture uses explicit stores and checks that disassembly includes all eight UAV writes. A separate compute and pixel fixture exercises three packed formats with distinct mip colors, point and linear filtering, full-chain and rebased views, and shader `Load`.

The exact FL11_1 selector enables copy-only `Rgba8Uint` textures when the driver reports native 2D, mip, and CPU-lockable support. The backend creates single-sample 2D resources with one layer in `DXGI_FORMAT_R8G8B8A8_UINT` and projects the format's texture-to-buffer bit to wgpu-core. Queue writes and all three copy directions share the existing transfer paths. The public fixture checks byte preservation across padded rows, partial copies into a nonzero mip of a non-power-of-two texture, and zero initialization on readback from a copy-source-only texture. The toggle is bound to device creation. The existing format projection applies in automatic mode and at earlier requested levels.

At exact FL11_1 the RTX 3090 Ti with driver 32.0.16.2101 passed all eight native tests and both public tests in x64 and x86. The x64 scoped CTS rerun at exact FL11_1 passed both `Rgba8Uint` copy cases, the third basic command-buffer case, and both storage-buffer-limit cases. Exact FL11_0 and FL9_1 each passed the third command-buffer case and both storage-limit cases and continued to reject the two integer copies. Every CTS run verified the exact requested hardware level and reported zero skips. The forced x64 FL9_1 public run repeated the baseline 7-versus-8 inter-stage limit failure with 176 passes.
